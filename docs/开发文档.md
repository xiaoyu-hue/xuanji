# 玄机 · 开发文档

面向维护者：如何构建、验证、改内容、发新版。

## 架构三层

| 层 | 目录 | 说明 |
|---|---|---|
| 核心层 | `core/` | Rust 库 `xuanji-core`：黄历（基于 lunar_rust）、抽签、答案、运势，全部纯逻辑 |
| 绑定层 | `web/` | Rust 库 `xuanji-web`：把核心函数包成 JSON 字符串接口，编译为 WebAssembly |
| 页面层 | `index.html` + `pkg/` | 静态页面（仓库根目录），GitHub Pages 直接托管 |

历法地基：[lunar_rust](https://github.com/flameoftheforest/lunar_rust)（MIT），
是 6tail 的 lunar 系列的 Rust 移植；核心层以 git 依赖方式引用它，
不要把它的代码复制进本仓库。

## 本地构建

前置：安装 Rust（含 `wasm32-unknown-unknown` 目标）与 wasm-bindgen 工具
（版本须与 `web/Cargo.toml` 中的 wasm-bindgen 依赖一致，当前为 0.2.130）。

```sh
rustup target add wasm32-unknown-unknown

# 1) 核心层自检（命令行演示四件套，含稳定性自检）
cd core && cargo run --release

# 2) 编译绑定层为 WebAssembly
cd ../web && cargo build --release --target wasm32-unknown-unknown

# 3) 生成页面用的 JS/WASM 包（--target web）
wasm-bindgen target/wasm32-unknown-unknown/release/xuanji_web.wasm \
  --out-dir ../pkg --target web
```

## 正确性验证（改核心后必做）

1. **与金标准对照**：历法字段（农历、干支、宜忌、冲煞、星宿、彭祖百忌、
   三神方位、值神、节气、星座）须与 6tail/lunar-javascript 对同一日期的
   输出逐项一致。已验过日期：2026-11-20、2026-02-17、2025-01-29、1986-05-29。
2. **WASM 与原生一致**：用 `--target nodejs` 再生成一份包，在 Node 里调用
   四个接口，与 `cargo run` 的输出对照，应完全相同。
3. **稳定性自检**：核心演示程序内置自检——同一天重复抽签/运势结果不变。

## 内容库（改内容不用动代码）

- `content/qian.json`：签库。字段：`id`（序号）、`grade`（签等，如 上上签/上签/
  中上签/中平签/下平签/下签）、`poem`（四句七言，数组）、`jie`（解签一句）。
  新增签时 id 顺延即可；抽签按日期哈希对签库总数取模，扩容后无需改代码，
  但**同一天的签会随总数变化而变**，属正常现象。
- `content/answers.json`：答案库，纯字符串数组，追加即可。
- 两份内容在编译期由 `include_str!` 嵌入核心，**改完内容必须重新编译 WASM**。

## 发布流程（GitHub Pages）

1. 完成构建与验证，把 `index.html` 与 `pkg/`（js、wasm、两个 .d.ts）提交到
   仓库根目录，`main` 分支即自动触发 Pages 构建。
2. **防缓存铁律**：每次发布新版 WASM，必须同步递增 `index.html` 里两处
   版本参数——模块导入 `xuanji_web.js?v=X.Y.Z` 与初始化
   `init('./pkg/xuanji_web_bg.wasm?v=X.Y.Z')`。
   否则老用户浏览器会继续用缓存的旧 WASM（1.1.0 首发时踩过此坑：
   页面是新的、签还是旧的）。
3. 代码与文档同步：功能变更同时更新 `README.md` 与 `CHANGELOG.md` 再提交。
4. 发布后实测：用真实浏览器打开线上地址，逐项点验四件套与新功能，
   并逐字核对当日签号与解签，确认加载的确实是新版核心。
