## 1. 设计目标与原则

玄机是一个纯静态站点的民俗文化娱乐应用：全部计算在使用者浏览器本地完成
（Rust 编译为 WebAssembly），无服务器、无数据库、不收集任何数据。
架构围绕六条原则展开，每条都有可核查的硬规则，不写空话。

### 1.1 低耦合（模块之间只经公开通道相连）

- 核心层每个体系一个文件，模块之间**禁止**引用对方的内部函数、常量与数据结构。
- 跨体系共享只允许走两个通道：共用层 `core/src/common.rs`（核心侧）、
  `site/js/ctx.js`（页面侧）。
- 页面功能模块之间**禁止**互相 import；需要共享状态时经 `ctx.state` 传递。

### 1.2 禁止超级巨型单文件

- 单个源文件软上限 **500 行**；超过必须按职责拆分，不允许以「先写着」为由累积。
- 现状（5.0.0）：最大的源文件是 `core/src/ziwei.rs`（270 行）；
  重构前 `core/src/lib.rs` 曾达 1000 行、九个体系挤在一个文件，是本次重构的直接动因。

### 1.3 避免过度设计

- 不引入前端框架（无 React/Vue 等），页面层是原生 ES 模块 + DOM；
  不引入构建工具链（无打包器），文件以 `<script type="module">` 直接加载。
- 不为「将来可能」预留抽象：没有第二个实现者需要替换的接口，不抽接口层；
  抽象只在出现真实复用（≥2 处）后提取到共用层。
- 服务端、账号、数据库在产品定位内明确不存在，不做任何预留设计。

### 1.4 Rust 为主

- 一切业务计算（历法、排盘、筛选、计分、随机定数）必须在 Rust 核心实现；
  页面层 JavaScript 只做四件事：取输入、调绑定、渲染结果、处理交互。
- 页面层禁止出现任何民俗规则判断（如宜忌筛选、生肖关系、五行生克）；
  出现即视为架构违规，规则必须下沉到核心。

### 1.5 可验算（每个体系都要有对拍标准）

- 每个计算体系上线前必须有**金标准**：权威开源实现或独立来源数据，
  逐字段/逐条对拍一致后才允许发布（见第 9 节）。
- 没有金标准、无法验算的体系不做（如面相、手相的图像判断），
  这是产品红线，不是技术限制。

### 1.6 故障隔离（一个功能坏掉，不许连坐全页）

- 页面每个功能模块独立初始化、独立失败：编排器逐个 try/catch，
  失败只在本功能卡片内显示提示，其余功能照常（见 7.2）。
- 核心长计算必须分段让出主线程（见 7.4），禁止一个功能冻结整个页面。
- 以上两条来自 4.0.1 / 4.0.2 两次真实事故，详见附录 A。

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ 页面层（每馆一个页面，共用样式）                              │
│   index.html（东方馆）   west.html（西方馆·待建）  mind.html（心智馆·待建） │
│        │  <script type="module">                              │
│   app.js 编排器 ── 逐个初始化、故障隔离                        │
│        │                                                      │
│   js/ 功能模块（每功能一文件）：almanac qian answers wedding  │
│       bazi bone hehun dreams ziwei share                      │
│   js/ctx.js 共享上下文        js/wasm.js 引擎加载器（只加载一次） │
└──────────────────────────┬───────────────────────────────────┘
                           │ JSON 字符串（见 5.2 接口契约）
┌──────────────────────────▼───────────────────────────────────┐
│ 接口层 xuanji-web（Rust / wasm-bindgen）                      │
│   每体系一个绑定文件，只做参数转换（i32→i64）与 JSON 序列化     │
└──────────────────────────┬───────────────────────────────────┘
                           │ 纯函数调用（公历年月日时分 → 结构体）
┌──────────────────────────▼───────────────────────────────────┐
│ 核心层 xuanji-core（纯 Rust，无 IO、无全局状态）               │
│   每体系一个模块：almanac qian answers bazi wedding bone      │
│                   hehun dreams ziwei                          │
│   common.rs 共用层：日期换算、种子哈希（无业务含义的纯工具）    │
│        │                                                      │
│   地基 lunar_rust（MIT，6tail lunar 的 Rust 移植）            │
│   内容 content/*.json（编译期 include_str! 嵌入各体系模块）    │
└──────────────────────────────────────────────────────────────┘
```

依赖方向**只能自上而下**：页面层 → 接口层 → 核心层 → 地基。
核心层不知道网页存在；接口层不写业务；页面层不算业务。

## 4. 核心层规范（xuanji-core）

### 4.1 模块划分

- 一个体系 = 一个文件 = 一个模块。体系的公开函数、结果结构体、私有辅助、
  私有常量（如称骨的骨重表、紫微的亮度表）全部收在本文件内。
- 模块对外只暴露：一个主函数（如 `bazi(...) -> Bazi`）与结果结构体。
  其余一律私有（不加 `pub`），从源头杜绝跨模块引用内部实现。
- `lib.rs` 只做两件事：声明模块、re-export 对外 API。
  调用方（接口层、自检程序）永远写 `xuanji_core::bazi(...)`，
  不写模块路径，日后调整内部分文件不影响调用方。

### 4.2 共用层准入（common.rs）

放进 `common.rs` 必须同时满足三条：

1. **无业务含义**：不出现任何民俗概念（生肖、五行、宜忌、星曜……）；
2. **纯函数**：无状态、无 IO、同输入同输出；
3. **真实复用**：已被 ≥2 个体系使用，或确定将被第二个体系使用。

当前成员：`days_from_civil` / `civil_from_days`（公历与天数互转，择日与紫微共用）、
`hash64` / `date_seed`（splitmix64 种子哈希，一签与答案之书共用）。
生肖表、五行生克这类「看着通用」的业务规则**不进**共用层——
它们目前只属于合婚一个体系，按 1.3 留在 `hehun.rs` 内，
等第二个体系真用到时再提取。

### 4.3 计算约定

- 入参一律公历（年、月、日、时、分，`i64`）+ 业务参数（性别 1 男 0 女等）；
  农历换算在模块内部经地基完成，调用方不接触农历对象。
- 结果一律 `#[derive(Serialize)]` 结构体，字段名 snake_case；
  字段增删属于接口变更，必须同步接口层、页面层与本文档第 13 节的模块表。
- 确定性：同一输入必须同输出。随机类功能（答案之书）的熵由调用方传入
  （`book_answer(entropy)`），核心不取系统随机，保证可复现、可验算。
- 日期定数类（一签）：以日期为种子经 `hash64` 打散后对库容取模；
  **库容变化会改变每一天的抽取结果**，扩库必须在 CHANGELOG 明示。
- 整数安全：地基在 32 位 WASM 上有过 usize 下溢崩溃（命宫计算，附录 A.4）；
  核心内一切减法索引换算一律用 `i64` 中转，禁止 usize 直接相减。

### 4.4 地基使用纪律

- 地基 `lunar_rust` 以 git 依赖引入（见 core/Cargo.toml），保证仓库源码可独立构建。
- 地基的已知缺陷在本层绕行并注释（八字模块有两处：大运结束年龄、命宫自算），
  **禁止**以「简化」为由删掉绕行代码；升级地基前先跑第 9 节全量对拍。
- 地基升级属于架构级变更：先评估（对照新版逐项对拍现有九体系锚点），再替换。

## 5. 接口层规范（xuanji-web）

### 5.1 绑定文件

- 与核心模块一一对应：一个体系一个绑定文件，`lib.rs` 只登记与 re-export。
- 绑定函数只做三件事：参数类型转换、调用核心、序列化为 JSON 字符串返回。
  绑定内出现任何判断逻辑（if/match 业务分支）即为违规，逻辑下沉核心。

### 5.2 接口契约

| 约定 | 内容 | 原因 |
|---|---|---|
| 参数类型 | 全部 `i32`（字符串除外），禁止 `i64` | wasm-bindgen 对 i64 参数要求 JS 传 BigInt，普通数字会直接报错（1.0.0 实测教训） |
| 返回类型 | 全部 `String`（JSON 文本） | 页面侧统一 `JSON.parse`，契约简单、无类型生成依赖 |
| 命名 | `<体系>_json`（答案之书沿用历史名 `book_answer`） | 与核心函数名可机械对应 |
| 错误 | 核心函数不返回 Result；非法输入由核心按约定兜底（如区间截断 400 天） | 页面无异常处理负担；兜底规则写进核心函数注释 |

### 5.3 WASM 构建

- 工具链：rustup 管理的 stable Rust + `wasm32-unknown-unknown` 目标；
  wasm-bindgen CLI 版本必须与 web/Cargo.toml 中的库版本一致（当前 0.2.130）。
- 产物四件（`xuanji_web.js` / `xuanji_web_bg.wasm` / 两个 `.d.ts`）进 `site/pkg/`，
  由 wasm-bindgen 生成，**禁止手改**；改绑定必须改源码后重新生成。

## 6. 内容层规范（content/）

- 一个体系一份数据文件（JSON），文件名即体系名；编译期由对应核心模块
  `include_str!` 嵌入。**改内容 = 改二进制**，必须重新编译 WASM 并递增版本号。
- 内容来源纪律（与代码同等严格）：
  - 优先原创（解梦 116 条、答案 100 条、合婚评语、塔罗牌义均为原创）；
  - 传统公共领域材料（骨重表、歌诀、卦辞）须 ≥2 个独立来源交叉核对，
    有分歧处记录取值与理由（称骨癸亥年取七钱，见开发文档）；
  - 古典化用必须如实标注（签库 12 首化用，README/使用说明已标注，2.0.2 起执行）；
  - 禁止整库复制任何在世作者或未授权来源的题库/词库/牌义。
- 数据文件格式变更（增删字段）属于接口变更，同步核心解析、页面渲染与自检断言。

## 7. 页面层规范（site/）

### 7.1 页面与卡片

- 一馆一页面：东方馆 `index.html`；西方馆、心智馆回归时各建 `west.html` / `mind.html`，
  共用 `style.css` 与 `js/ctx.js`、`js/wasm.js`，各自带本馆的编排器与功能模块。
- 一功能一卡片：卡片 `<section class="card" data-mod="<模块名>">`，
  `data-mod` 是故障提示的定位锚（见 7.2），新增卡片必须同时登记。

### 7.2 编排器与故障隔离（强制）

`app.js` 是编排器，只做三件事：加载引擎、显示日期、逐个初始化功能模块。
初始化必须走如下模式（5.0.0 起的硬性规定）：

```js
for (const [key, name, init] of FEATURES) {
  try { init(w); }
  catch (e) { /* 在 data-mod=key 的卡片内追加一句提示，其余模块继续 */ }
}
```

- 禁止把功能代码直接写进编排器；禁止一个模块的顶层代码在 import 时执行 DOM 操作
  （一切初始化只在 `init(w)` 被调用时发生）。
- 引擎（WASM）加载失败是唯一允许的全页级失败，走 `main().catch` 提示刷新。

### 7.3 功能模块

- 一功能一文件，放 `site/js/`，导出单个 `init(w)`；`w` 是接口层绑定对象。
- 模块内只准出现：读本卡片输入 → 调 `w.<体系>_json` → 渲染本卡片。
  需要共享状态经 `ctx.state`（当前：黄历数据、最近一签，供分享图模块读）。
- 元素引用统一用 `ctx.js` 的 `el(id)` 或页面具名全局；**每个模块用到的工具
  必须在文件头 import 写明**——4.0.1 事故的直接原因就是工具漏定义 + 入口漏登记
  （附录 A.1），新增模块时对照第 11 节清单逐项核。

### 7.4 长计算分段（强制）

- 凡单次点击触发的计算预计超过约 200ms（如逐日扫描类），必须分段执行：
  每段 ≤3 天（择日现行值），段间 `await new Promise(r => setTimeout(r, 10))`
  让出主线程，并实时更新进度文案（已查 N/总天数、先找到 M 个）。
- 扫描期间触发按钮置 `disabled` 防重复启动；输入参数在开扫时快照，
  中途改输入不影响本次结果。
- 分段与一次算完的结果必须逐条一致（4.0.2 已对拍验证），分段只是调度手段，
  不许改变核心函数的语义与结果顺序。

### 7.5 缓存与版本参数（防缓存铁律）

- GitHub Pages 对静态资源下发 `Cache-Control: max-age=600`，且 HTML 本身也会被缓存；
  全部资源引用统一带 `?v=<版本号>`：`index.html` 的 style/script 引用、
  `app.js` 对 `js/*` 的 import、`js/*` 之间的 import、`js/wasm.js` 对 `pkg/*` 的引用，
  **无一例外**。同一发布内所有 `?v=` 必须同值。
- 每次发布必须递增版本号并全量替换上述引用（用脚本批量替换后 grep 复核计数）。
  漏掉一处 = 部分用户拿到新旧混合文件 = 4.0.1 式事故的变体。
- 模块 URL 不同即不同实例：同一文件被以「带 ?v=」与「不带 ?v=」两种路径引用时，
  浏览器会加载两份、共享状态失效——这是 7.5 必须全量统一的根本原因。

### 7.6 样式

- 全站一份 `style.css`，按「基础 → 卡片 → 各功能专属类」顺序组织；
  功能专属类以功能前缀命名（如 `.zwcell` 属紫微、`.wday` 属择日）。
- **禁止整段批量删除样式类**：3.0.0 曾因批量清理误删八字共用的五行条样式
  （附录 A.3）。删类前必须先列「页面实际在用类名」与样式表做差集，只删差集部分。

## 8. 依赖规则总表

| 谁 | 可以依赖 | 禁止依赖 |
|---|---|---|
| 页面功能模块 `js/<功能>.js` | `ctx.js`、`w`（绑定对象）、本卡片 DOM | 其他功能模块、pkg 内部实现 |
| 编排器 `app.js` | `wasm.js`、`ctx.js`、各功能模块的 `init` | 在编排器内写功能逻辑 |
| 接口层绑定 `web/src/<体系>.rs` | 对应核心模块的公开 API | 其他体系的核心模块、核心模块内部 |
| 核心模块 `core/src/<体系>.rs` | `common.rs`、地基 lunar_rust、本体系内容文件 | 其他核心模块的一切（函数/常量/结构体） |
| 共用层 `common.rs` | 标准库 | 地基、任何业务概念 |
| 自检程序 `core/src/main.rs` | 核心对外 API（经 lib.rs re-export） | 核心模块内部路径 |

## 9. 验算体系（质量门）

每个体系过四道关，缺一不可，全过才许发布：

1. **原生自检**：锚点用例写进 `core/src/main.rs`（或体系约定的自检函数），
   `cargo run --release` 断言全过。锚点来自金标准实测值，不许凭记忆写。
2. **金标准对拍**：
   - 历法/八字类 → `6tail/lunar-javascript`（MIT）逐字段比对；
   - 紫微 → `iztro` 2.6.5（MIT）随机批量对拍（现行 82 盘逐项一致）；
   - 传统表格类（称骨）→ ≥3 个独立来源交叉核对，分歧点留痕；
   - 新体系立项时先定金标准，无金标准不开工（见 1.5）。
3. **WASM 对拍**：重编后在 Node 里调全部绑定，核对导出清单与锚点值
   与原生一致（防接口层转换错误，如 i32/i64 问题）。
4. **公网点验**：发布后用真实浏览器打开线上地址，逐个功能实际操作，
   与预期值逐项核对；注意 Pages 有 10 分钟缓存，点验前先确认加载的是新版
   （看版本号特征，如预填值/新卡片），必要时强刷或等缓存过期复验。

## 11. 新增一个体系的标准流程

1. **立项调研**：查开源实现与许可证（只用 MIT/Apache/公有领域等干净来源做地基或
   金标准；AGPL/无许可证只许看思路），定金标准与锚点用例，报用户拍板。
2. **内容先行**：内容文件落 `content/<体系>.json`（或模块内常量），过第 6 节来源纪律。
3. **核心模块**：新建 `core/src/<体系>.rs`，只依赖 `common` 与地基；
   在 `lib.rs` 登记模块与 re-export。
4. **自检**：锚点断言进 `main.rs`，金标准对拍通过。
5. **接口绑定**：新建 `web/src/<体系>.rs`，`web/src/lib.rs` 登记；重编 WASM 并对拍。
6. **页面模块**：新建 `site/js/<体系>.js`（只依赖 ctx 与 w）；
   `index.html` 加卡片（带 `data-mod`）；`app.js` 的 FEATURES 表登记。
   长计算按 7.4 分段。
7. **文档**：README 功能表、使用说明、CHANGELOG、本架构文档第 13 节模块表同步。
8. **发布**：走第 10 节清单，公网点验通过后才算完成。

## 附录 A. 历史教训（每条对应一条现行规范）

**A.1 4.0.1 接线事故**：4.0.0 五个新功能的页面脚本漏定义共用工具 `el`、
五个新入口漏入 import 清单，初始化在择日一节抛错，其后全部功能静默失效
（黄历等先行初始化的功能正常，极具迷惑性）。
→ 对应规范：7.2 故障隔离、7.3 工具 import 明示、第 10 节「三处登记」检查项。

**A.2 4.0.2 择日卡死**：逐日宜/忌计算单日成本高（本地实测 30 天约 19 秒），
原实现一次算完默认 180 天，主线程被占满，全页按钮无响应，被误报为多个功能卡死。
→ 对应规范：7.4 长计算分段（每段 ≤3 天 + 进度 + 让出主线程）。

**A.3 3.0.0 样式误删**：批量清理「无用」样式类时误删了八字五行条与择日共用的类，
页面局部裸奔，靠与旧版样式表 diff 才发现。
→ 对应规范：7.6 删类前先做在用类名差集。

**A.4 地基 32 位溢出**：lunar_rust 的命宫计算在 wasm32 上 usize 相减下溢崩溃；
大运结束年龄误返年份。均已在核心层自算绕行并注释（bazi.rs）。
→ 对应规范：4.3 整数安全、4.4 地基缺陷绕行纪律。

**A.5 缓存连环误判**：Pages 的 600 秒缓存多次让验收看到旧页面/旧 WASM，
出现过「修了没生效」「签号对不上」的假故障。
→ 对应规范：7.5 版本参数全量统一、第 9 节第 4 关先验版本特征再下结论。

**A.6 5.0.1 路径基准事故**：引擎加载器移入 `js/` 子目录后，
`init('../pkg/…wasm')` 的字符串路径被浏览器按**页面地址**而非模块地址解析，
少一层目录导致 WASM 404、首屏初始化整体失败；本地 Node 对拍不经过页面
加载路径，未能提前发现，靠公网回归拦截。
→ 对应规范：模块内引用静态资源（WASM 等）的地址必须以
`new URL(路径, import.meta.url)` 按模块自身位置构造，禁止裸相对字符串；
第 9 节第 4 关（公网点验）是此类问题的唯一可靠拦截点，不可省略。
